# 普通預金システム 移行前レビュー ハンズオン

COBOLのバッチをJavaへ移行する前に、Claude Code で要件定義書と既存コードの問題点を洗い出し、結果を自分で確かめるハンズオンです。

本リポジトリの銀行、業務、数値、データはすべて研修用に作成した架空のものです。実在の企業やシステムとは関係がありません。

## あなたの役割

あなたは、引き継いだCOBOLシステムのJava移行を任された担当者です。要件定義書は残っていますが、現行のコードと一致しているかは分かりません。

AIに洗い出しをさせた後、次の問いに答えてください。

> **指摘のうち、本当に重要なのはどれか。その指摘は正しいと言えるか。**

COBOLを読めなくても大丈夫です。分からないところは Claude Code に聞いてください。

## 事前準備（当日までに）

必要なものは git、Claude Code、ブラウザです。COBOLやJavaのビルド環境は要りません。

**VS Code を推奨します。** 当日は要件定義書とコードの該当行を何度も見比べます。レポートのリンクから、GitHub か VS Code で該当行を直接開けます。行番号へ移動できるエディタなら、ほかのものでも構いません。

### 1. 取得する

```bash
git clone https://github.com/takuyakubo/dev-automation-workshop.git
cd dev-automation-workshop
git checkout start
```

**内容は当日までに更新することがあります。** 前日以降に、いったんフォルダを削除して取得し直してください（上の3行をもう一度実行します）。

### 2. Claude Code の動作を確かめる

```bash
claude
```

- 最初にこのフォルダを信頼するかを聞かれたら、信頼する側を選びます。これを選ばないと、`.claude/settings.json` の許可設定が使われず、当日の検出が書き込みの確認で止まります
- ログインを求められたら、所属先で案内された方法でログインします
- 起動したら「このリポジトリの構成を一言で教えて」などと入力し、応答が返ることを確かめます。確認できたら `/exit` で終了します

### 3. レポートを開けることを確かめる

`report/index.html` をブラウザで開きます。「findings.json をここにドロップ」と表示されれば準備完了です。

**費用と時間の目安：** 検出コマンドの実行1回につき、約3〜17分、APIの定価に換算して約1ドルかかりました（講師の環境で6回試した結果です）。実行する環境によって変わります。Claude Code の費用は各自の所属先の負担です。

## 当日の手順

### 1. 休憩の前に検出を始める

```bash
claude
```

Claude Code の中で次を入力します。

```text
/findings
```

動き始めたことを確かめたら、休憩に入って構いません。PCはスリープしないようにしてください。完了すると `findings/findings.json` ができます。

### 2. 結果をレポートで見る

`report/index.html` をブラウザで開き、`findings/findings.json` をドロップします。ファイルはブラウザの中で読むだけで、外部には送信しません。

あわせて、リポジトリの直下で `code .` を実行し、VS Code で開いておきます（`code` コマンドがなければ、VS Code の「フォルダーを開く」でリポジトリを開きます）。レポートの「VS Code で開く」を押すと、要件定義書やコードの該当行が開きます。初回はブラウザが「VS Code を開くか」を確認するので、許可します。

### 3. 根拠を確かめて3件選ぶ

重大度の高いものから順に、要件定義書とコードの該当箇所を見比べます。AIの説明だけで判断せず、元の記述を読んでください。

指摘ごとに「正しい」「誤検出」「判断できない」のいずれかを記録し、本当に重要だと思う3件を選びます。

迷ったら Claude Code に質問できます。ただし、その答えもAIの説明です。

### 4. 比較して議論する

選んだ3件を「共有用にコピー」でコピーし、他の人の結果と見比べます。同じコマンドでも、結果は人ごとに変わります。

時間が余ったら、指摘を1件選び、Claude Code で直してみてください。

## 指摘の見方

| 項目 | 値 | 意味 |
|---|---|---|
| 分類 | 誤り | 正解がある状態で、何かがおかしい。法令などの外部の基準も正解に含める |
| | 矛盾 | 正解はないが、2つ以上の記述が異なる |
| | 未定義 | 書くべきことが書かれていない |
| 領域 | 業務ロジック | 入出金と利息の計算そのもの |
| | 営業依存 | 時間外、営業日、手数料など、営業や運用の決めで変わるもの |
| | 基盤・移行・文書 | 上の2つに入らないもの（照合順序、障害回復、非機能など） |
| 外部の基準 | | 根拠にした法令などの出典と確認日。確認していなければ「未確認」 |

レポートの「機械のチェック」は、AIを使わずに形式と参照先の実在だけを確かめます。合格でも、指摘の内容が正しいとは限りません。

## 用語集

| 用語 | 意味 |
|---|---|
| ブラウンフィールド | すでに動いているシステムがある状態での開発。何もないところから作る場合はグリーンフィールドと呼ぶ |
| ファインディングス | レビューで見つかった指摘事項 |
| COBOL | 金融機関などの基幹システムで長く使われてきたプログラミング言語 |
| 普通預金 | 出し入れが自由で、利息がつく預金 |
| バッチ | データをまとめて処理する方式。夜間に実行することが多い |
| コピーブック | COBOLで複数のプログラムが共有するレコード定義。`legacy/COPYBOOK/` にある |
| `PIC` | COBOLで項目の型と桁数を定める指定。`PIC 9(5)` は5桁の数字 |
| EBCDIC | メインフレームで使われてきた文字コード |
| V字モデル | 要件、設計、実装と、それぞれに対応するテストを組にして進める開発の考え方 |

## ファイルの構成

| パス | 内容 |
|---|---|
| `docs/requirements.md` | 移行要件定義書 |
| `legacy/` | 現行のCOBOLプログラムとサンプルデータ |
| `.claude/commands/findings.md` | 検出コマンド `/findings` の内容 |
| `.claude/settings.json` | Claude Code の許可設定。書き込みを `findings/` の中に限り、Web検索を止める |
| `findings/` | 検出結果の出力先 |
| `report/` | HTMLレポートとチェック処理。AIを使わず、毎回同じ形で表示する |
| `tools/` | 題材の管理用スクリプト（Node.js）。ワークでは使わない |

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| `/findings` が見つからない | リポジトリの直下で `claude` を起動しているか確かめる |
| 書き込みの確認で止まる | 内容を確かめて許可する。最初の信頼の確認で「信頼しない」を選んだ場合に起きる |
| 休憩から戻っても終わっていない | そのまま待つ。間に合わなければ講師が結果の例を案内する |
| レポートに読み込めない | `findings/findings.json` が書かれているか、JSONとして壊れていないかを確かめる |
| レポートが前の結果を表示する | 右上の「別のファイルを読み込む」を押す |
